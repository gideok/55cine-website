# 스크롤 스냅 캐러셀 (Scroll-snap carousel)

## 명칭

- **영문**: *scroll-snap carousel*, *CSS carousel*, *overflow carousel* 등으로 불립니다. [MDN «Creating CSS carousels»](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Overflow/Carousels)에서는 가로 스크롤·스냅·슬라이드 구조를 **CSS 캐러셀** 패턴으로 설명합니다.
- **한글**: 구현 맥락에 따라 **스크롤 스냅 캐러셀**, **가로 스와이프 캐러셀**, **페이지 단위 캐러셀** 등으로 부릅니다. 접근성 문맥에서는 `role="region"` + `aria-roledescription="캐러셀"` 조합이 흔합니다.
- **기획전 테스트 페이지와의 관계**: `special-exhibition-test.html`의 목록은 “페이지 번호만 바꾸는 전통적 페이지네이션”이 아니라, **한 뷰포트 너비 = 한 페이지**인 **가로 스크롤 스냅 기반 캐러셀**이며, 하단의 이전/다음·분수 표기·점(dots)은 **캐러셀 크롬(carousel chrome)** / **페이지 인디케이터**에 해당합니다.

## 이 프로젝트에서의 핵심 구조

### 1. 마크업

- 바깥: `overflow-x: auto`인 **뷰포트** (`se-swipe-viewport`, 포커스·키보드용 `tabindex="0"`).
- 안쪽: 가로 `display: flex` **트랙** (`se-swipe-track`).
- 각 **슬라이드** (`se-slide`)는 뷰포트 너비의 `flex: 0 0 100%`로 한 화면에 하나만 보이게 합니다.
- 슬라이드 안에 실제 카드 그리드 (`se-grid`)를 두어, “한 페이지”에 여러 아이템을 배치합니다.

### 2. CSS

- 뷰포트에 `scroll-snap-type: x mandatory` — 가로 방향 **필수 스냅**.
- 슬라이드에 `scroll-snap-align: start` (및 필요 시 `scroll-snap-stop: always`) — 스크롤이 멈출 때 **슬라이드 시작선**에 맞춤.
- `scroll-behavior: smooth` — 버튼·스크립트의 `scrollTo` 시 부드러운 이동 (`prefers-reduced-motion`에서는 비활성화 권장).

### 3. JavaScript

- **페이지 수**: `totalPages = ceil(데이터 길이 / itemsPerPage)`  
  `itemsPerPage`는 뷰포트·열 수·셀 높이(썸네일 비율 + 제목 영역 예약 높이)로 **동적 계산**하면 화면 높이를 채우는 그리드와 맞물립니다.
- **슬라이드 DOM**: 페이지마다 슬라이드 하나를 만들고, 그 안에 해당 구간의 아이템만 채웁니다 (`buildSlides` / `buildThumbSlides` 패턴).
- **활성 페이지와 스크롤 동기화**  
  - `scrollLeft`와 `clientWidth`로 `round(scrollLeft / width)` → 현재 슬라이드 인덱스.  
  - `scroll` 디바운스 + `scrollend`(지원 시)로 크롬(분수·dots·버튼 disabled) 갱신.
- **이전/다음**: `viewport.scrollTo({ left: pageIndex * clientWidth, behavior: 'smooth' })` 로 **스크롤 위치**를 바꿉니다 (DOM만 갈아끼우는 방식이 아님).
- **dots**: 각 점은 해당 슬라이드 인덱스로 스크롤; 보조 기술과 중복 안내를 피하려면 컨테이너에 `aria-hidden="true"`를 두고 점 자체에 `aria-label`만 두는 식으로 조정할 수 있습니다(기획전 테스트와 동일 취지).
- **키보드**: 뷰포트에 포커스가 있을 때 `ArrowLeft` / `ArrowRight`로 페이지 이동.
- **리사이즈**: `resize` + (가능하면) `ResizeObserver`로 뷰포트 크기 변화 시 `itemsPerPage` 재계산 후 슬라이드 재구성; **이전에 보던 데이터 오프셋**(`activePage * oldItemsPerPage`)을 보존해 새 `activePage`를 잡으면 페이지 경계가 자연스럽습니다.

## 매거진 프리뷰 썸네일형에 적용 시 요약

- 목록형은 기존처럼 **고정 건수/페이지 + DOM 교체** 페이지네이션을 유지합니다.
- 썸네일형은 `special-exhibition-test.html`과 같은 **스크롤 스냅 캐러셀 + 동적 itemsPerPage + 하단 크롬**으로 통일했습니다 (`test/js/test-ti-magazine-preview-page.js`, `test/css/test-ti-magazine-preview.css`).

## 작업 시 주의사항

다음은 매거진 프리뷰 테스트 UI에 캐러셀·목록 토글을 붙이면서 실제로 겪었거나, 재발을 막기 위해 문서화한 점입니다.

### 1. `[hidden]`과 `display`의 충돌

- HTML `hidden` 속성은 보통 `display: none`에 해당하지만, 프로젝트 CSS에서 `.preview-list { display: grid }`처럼 **표시 방식을 지정한 규칙이 더 높은 특이도**이면 숨김이 무시될 수 있습니다.
- 그 결과 썸네일형에서도 목록 그리드가 겹쳐 보일 수 있으므로, 숨겨야 하는 루트에는 예를 들어 `.preview-list[hidden], .mz-thumb-stack[hidden] { display: none !important; }`처럼 **명시적으로 덮어쓰기**를 두는 것이 안전합니다.

### 2. 캐러셀 ↔ 다른 보기 모드 전환 시 DOM 정리

- 한 페이지에 **캐러셀 트랙**과 **목록 컨테이너**를 같이 두는 경우, 모드만 바꾸고 DOM을 비우지 않으면 이전 모드의 마크업·스타일이 남아 보일 수 있습니다.
- 모드 전환 시 **반대쪽 영역을 비우는** 처리(예: 목록으로 갈 때 캐러셀 트랙 `innerHTML` 비우기 및 `scrollLeft` 초기화, 썸네일로 갈 때 목록 컨테이너 비우기)를 습관화하는 것이 좋습니다.

### 3. 썸네일 그리드에서 “같은 행” 박스 높이 맞추기

- CSS Grid의 행 높이는 기본적으로 해당 행에서 **가장 큰 셀**을 따르지만, 카드 내부가 `flex`로만 쌓여 있으면 **제목 박스(`.preview-body`)만 내용 높이만큼** 남고 아래가 들쭉날쭉해 보일 수 있습니다.
- 카드(`.preview-item`)를 세로 `flex`로 두고 `height: 100%`, `align-self: stretch`, `min-height: 0`으로 그리드 셀을 채운 뒤, 썸네일 링크는 `flex-shrink: 0`, 본문은 `flex: 1 1 auto`로 두면 **행 높이에 맞춰 본문 영역이 늘어나** 시각적으로 정돈됩니다. 그리드에는 `align-items: stretch`를 명시해 두는 편이 분명합니다.

### 4. 열 수·페이지당 개수·CSS 변수 동기화

- `itemsPerPage`를 “뷰포트 높이 + 열 수 + 셀 높이”로 계산한다면, **그리드의 실제 `grid-template-columns` 열 수**와 반드시 일치해야 합니다. 열만 CSS 미디어쿼리로 고정하고 JS만 넓은 범위로 계산하면 한 슬라이드에 들어가는 칸 수와 계산이 어긋납니다.
- 열 수를 JS에서 구한 뒤 `style.setProperty('--mz-thumb-cols', …)`처럼 **커스텀 프로퍼티로 그리드에 전달**하고, `repeat(var(--mz-thumb-cols, 4), minmax(0, 1fr))`처럼 쓰면 한곳에서 맞출 수 있습니다. 뷰포트 너비와 최소 셀 폭으로 열 수를 구하는 방식이면, 단순 2·4단 고정보다 리사이즈에 잘 따릅니다.

### 5. 슬라이드 재빌드 조건

- `itemsPerPage`가 같아도 **열 수만 바뀌면** 슬라이드 안 그리드 배치가 달라져야 하므로, `열 × 페이지당개수`만으로 키를 잡거나 데이터 길이까지 포함한 **레이아웃 키**로 “다시 그릴지”를 판단하는 것이 안전합니다.
- 데이터가 비동기로 늘어나는 경우, 길이가 바뀌었는데 키가 같으면 슬라이드 수가 틀어질 수 있으므로 **데이터 건수** 등을 키에 넣는 것을 권장합니다.

### 6. 썸네일 전용 마크업과 목록 전용 마크업

- 같은 팩토리 함수로 카드를 만들되, 썸네일형에서는 요약(excerpt) 노드를 **아예 생성하지 않는** 방식이면, `display: none`만으로 숨기는 것보다 DOM·접근성 측면에서 분리가 분명해집니다.
- 목록형에서만 긴 본문·요약이 필요하면 플래그 인자 등으로 분기하는 편이 유지보수에 유리합니다.

### 7. dots·이벤트 위임

- 목록형은 `data-page`와 이벤트 위임으로 점 클릭을 처리하고, 썸네일형은 슬라이드마다 점에 리스너를 붙이는 식으로 **패턴이 다를 수 있습니다**. 한 컨테이너에 위임만 쓸 경우 `currentView` 등으로 **캐러셀 모드에서는 위임 핸들러가 동작하지 않게** 막아 중복 처리가 없도록 합니다.
