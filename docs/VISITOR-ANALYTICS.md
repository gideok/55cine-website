# 방문자 분석 가이드 — 유입경로 · 페이지뷰 · 체류시간

> **대상:** 55CINE 오오극장 웹사이트 (`55cine-website`)  
> **목적:** 사용자가 **어디서 들어왔는지(유입경로)**, **어떤 페이지를 봤는지**, **얼마나 머물렀는지(체류시간)** 를 확인하기 위한 진행 방안 정리  
> **현재 상태:** 저장소 기준 Google Analytics·Plausible·자체 수집 스크립트 **미적용** (2026-06 기준)

---

## 1. 먼저 정할 것

분석 도구를 고르기 전에 아래를 팀에서 합의하는 것이 좋습니다.

| 항목 | 질문 |
|------|------|
| **목표** | 상영작 홍보 효과? 매거진 읽기 깊이? 예매 전환? 전체 트래픽만? |
| **담당** | 누가 대시보드를 주기적으로 볼 것인가 |
| **보관 기간** | 3개월 / 1년 / 무기한 |
| **개인정보** | 쿠키 배너·개인정보 처리방침 갱신 필요 여부 |
| **예산** | 무료 SaaS / 유료 SaaS / 서버 자원(자체 호스팅) |
| **정확도** | 대략적 추이면 충분한지, 캠페인별 숫자까지 필요한지 |

**체류시간**은 “페이지를 연 뒤 실제로 읽은 시간”에 가깝게 만들려면 브라우저 측 이벤트(가시 영역·탭 전환 등)가 필요합니다. 서버 액세스 로그만으로는 **정확한 체류시간을 알 수 없습니다.**

---

## 2. 현재 사이트 구조와 수집 방식에 미치는 영향

```
브라우저 → Nginx (:80) → 정적 HTML/CSS/JS/images (/var/www/55cine)
                      → /api/* → Fastify (Node, :3000) → MS SQL
```

| 특성 | 분석에 대한 의미 |
|------|------------------|
| **멀티 페이지 HTML** | 페이지 이동마다 전체 로드 → 페이지뷰·유입은 **페이지 단위**로 수집하기 쉬움 |
| **일부 JS 동적 목록** | 상영작·매거진 목록은 API로 채움 → “목록 페이지 방문”과 “상세까지 진입”은 **별도 이벤트**로 나누는 것이 좋음 |
| **관리자 (`/admin/`)** | 운영 트래픽과 섞이지 않도록 **제외 필터** 필요 |
| **로컬·스테이징** | `localhost`, 사설 IP, 테스트 호스트는 **수집 제외** 권장 |

---

## 3. 수집 항목 정의 (용어 통일)

### 3.1 유입경로 (Acquisition / Referrer)

| 지표 | 설명 | 예시 |
|------|------|------|
| **Referrer** | 이전 사이트 URL | `instagram.com`, `google.com`, `(direct)` |
| **UTM 파라미터** | 링크에 붙이는 캠페인 태그 | `?utm_source=instagram&utm_medium=social&utm_campaign=gv` |
| **유입 매체 구분** | 검색 / SNS / 직접 / 외부 링크 / 이메일 등 | 보고서에서 묶어서 표시 |

**운영 팁:** 인스타·뉴스레터·포스터 QR 등 **보내는 모든 링크**에 UTM을 붙이면, “어디서 왔는지”를 referrer보다 안정적으로 추적할 수 있습니다.

### 3.2 페이지뷰 (Page view)

| 지표 | 설명 |
|------|------|
| **페이지 경로** | `/now-playing.html`, `/magazine/preview/article-detail.html?id=…` |
| **페이지 제목** | `<title>` 또는 커스텀 라벨 |
| **세션 내 순서** | 1번째 → 2번째 → … (동선) |

상세 URL에 `?slug=`, `?id=` 가 붙는 페이지는 **경로 패턴을 정규화**할지(예: `/movies/movie-detail.html` 로 묶기) 정책을 정합니다.

### 3.3 체류시간 (Engagement / Dwell time)

| 방식 | 정확도 | 설명 |
|------|--------|------|
| **서버 로그** | 낮음 | 요청 시각 차이만 추정 가능, 탭 이탈·뒤로가기 반영 어려움 |
| **페이지 로드 ~ unload** | 중간 | 탭을 닫지 않고 이탈하면 과대/과소 |
| **Page Visibility API** | 높음 | 탭이 **보이는 동안만** 시간 누적 (권장) |
| **하트비트(15~30초 ping)** | 높음 | SPA·긴 읽기 페이지에 유리 |

**권장 정의:** “해당 페이지가 브라우저에서 **visible 상태였던 누적 초**”를 공식 체류시간으로 삼습니다.

## 4. 구현 경로 비교

### 4.1 1단계 — 서버 액세스 로그 (코드 변경 없음, 즉시 가능)

Nginx `access.log` 만으로도 다음은 **대략적**으로 확인 가능합니다.

- 일별·시간대별 방문 수(요청 수)
- 많이 요청된 URL
- Referer 헤더(유입 URL, 없으면 direct에 가까움)
- User-Agent(모바일/PC 비율)

**한계:** 체류시간 불가, JS·API만 호출한 경우와 HTML 방문 구분 어려움, 봇 포함, 캐시·CDN 사용 시 로그 위치 달라짐.

**진행:** 운영 서버에서 `goaccess`, `AWStats`, 또는 로그를 S3/CloudWatch 등으로 보내 대시보드 구성.

---

### 4.2 2단계 — 분석 SaaS (프론트 스크립트 1회 삽입)

공통 페이지 레이아웃(`partials/`, `shell` 공통 스크립트)에 **추적 스니펫 1곳**만 넣으면 대부분의 HTML 페이지에 적용됩니다.

| 도구 | 유형 | 유입·페이지 | 체류시간 | 비고 |
|------|------|------------|----------|------|
| **Google Analytics 4 (GA4)** | 클라우드 | ◎ | ◎ (engagement time) | 무료, 학습 곡선·쿠키·개인정보 고지 필요 |
| **Plausible** | 클라우드 | ◎ | △ (기본은 체류 제한적, Goals/커스텀 가능) | 경량, EU 호스팅, 유료 |
| **Umami** | 셀프호스트 or Cloud | ◎ | △ | 오픈소스, 서버에 Docker로 설치 가능 |
| **Matomo** | 셀프호스트 or Cloud | ◎ | ◎ | GA 대체, 온프레미스 가능, 설정 부담 큼 |

**55CINE에 맞는 현실적 선택:**

- **빠르게 보고서만 필요** → **GA4** (또는 팀이 프라이버시를 중시하면 **Plausible / Umami**)
- **데이터를 자사 서버에만 두고 싶음** → **Umami** 또는 **Matomo** (`/var/www` 와 별도 서브도메인 `stats.55cine.com` 등)

**체류시간:** GA4는 `user_engagement`, `session_duration` 등 기본 제공. Plausible/Umami는 “평균 체류”보다 **페이지뷰·유입·이벤트** 중심이므로, 체류가 핵심 KPI면 GA4·Matomo·자체 수집을 우선 검토합니다.

---

### 4.3 3단계 — 자체 수집 (Fastify API + DB)

이미 **Node API + MS SQL** 이 있으므로, 장기적으로는 아래 구조도 가능합니다.

```
브라우저 (공통 analytics.js)
  → POST /api/v1/analytics/events  (배치·beacon)
  → Fastify
  → dbo.web_analytics_event (신규 테이블)
  → 관리자 대시보드 또는 Metabase/Excel
```

**수집 이벤트 예시**

| event_type | 필드 예 |
|------------|---------|
| `page_view` | path, title, referrer, utm_*, session_id, device |
| `page_leave` | path, visible_ms |
| `heartbeat` | path, visible_ms (30초마다) |

**장점:** 스키마·보관 기간·관리자 제외를 완전 통제.  
**단점:** 개발·운영·개인정보·봇 필터·대시보드까지 직접 구현. **1단계 SaaS로 요구사항 검증 후** 검토하는 것을 권장합니다.

## 5. 권장 진행 순서 (로드맵)

### Phase A — 요구사항·법무 (1주)

1. 측정할 KPI 표 작성 (유입 TOP5, 핵심 페이지 10개, 평균 체류 목표)
2. **개인정보 처리방침**에 “접속 로그·쿠키·분석 도구” 문구 추가 여부 법무/운영 검토
3. 쿠키 배너 필요 여부 결정 (GA4 등 쿠키 사용 시)
4. `/admin/*`, 내부 IP, 봇 제외 규칙 문서화

### Phase B — 무코드·저비용 기초 (즉시~1일)

1. Nginx access log 로테이션·보관 확인
2. (선택) `goaccess` 등으로 주간 TOP URL·Referrer 리포트
3. SNS·포스터·뉴스레터 링크에 **UTM 규칙** 표준화  
   - 예: `utm_source`, `utm_medium`, `utm_campaign` 네이밍 가이드 배포

### Phase C — 분석 도구 도입 (1~3일)

1. GA4(또는 Plausible/Umami) **속성·데이터 스트림** 생성
2. 공통 삽입 위치 결정  
   - 후보: `partials/` 공통 푸터, `js/site-footer-include.js` 직후, `shell` 공통 head
3. 스테이징·운영 도메인 분리 (개발 트래픽 필터)
4. **향상된 측정(Enhanced measurement)** / 이벤트:  
   - 아웃바운드 클릭(예매 링크)  
   - 파일 다운로드  
   - 스크롤(매거진 기사)

### Phase D — 체류시간·동선 고도화 (1~2주)

1. 페이지별 **visible 시간** 이벤트 (Visibility API) — 상세 기사·상영작 상세 우선
2. 목록 → 상세 **퍼널** 이벤트 (`view_item_list`, `select_content` 등 GA4 권장 이벤트명)
3. 관리자·로컬 호스트 **제외** 검증
4. 월 1회 리포트 템플릿 (유입 매체 / TOP 페이지 / 평균 체류 / 모바일 비율)

### Phase E — (선택) 자체 DB·관리자 리포트

Phase C에서 3~6개월 운영 후, SaaS 한계(데이터 소유·맞춤 리포트)가 있으면 Phase 4.3 설계 착수.

## 7. 개인정보·컴플라이언스 (한국 기준 체크리스트)

- [ ] **개인정보 처리방침**에 분석 목적, 수집 항목(IP·쿠키 ID 등), 보관 기간, 거부 방법 명시
- [ ] 제3자 제공(Google 등) 시 **위탁·국외 이전** 여부 기재
- [ ] 쿠키/유사 기술 사용 시 **사전 고지·동의** 방식 결정 (필수·선택 쿠키 구분)
- [ ] IP **마스킹·익명화** 옵션 활성화 (GA4: IP 기반 위치만, 정책에 맞게 설정)
- [ ] 분석 데이터에 **이름·전화·이메일** 등 직접 식별 정보 넣지 않기
- [ ] 관리자 로그인·내부 테스트 트래픽 **필터**

※ 법무 검토는 이 문서로 대체할 수 없습니다. 운영 주체에 맞게 최종 확인이 필요합니다.

## 8. UTM 링크 운영 가이드 (요약)

캠페인 링크 예시:

```
https://55cine.com/now-playing.html?utm_source=instagram&utm_medium=social&utm_campaign=2026_spring_gv
```

| 파라미터 | 예시 | 의미 |
|----------|------|------|
| `utm_source` | `instagram`, `newsletter` | 유입 출처 |
| `utm_medium` | `social`, `email`, `qr` | 매체 유형 |
| `utm_campaign` | `2026_spring_gv` | 캠페인명 |
| `utm_content` | `poster_a` | (선택) 소재 구분 |

팀 내 **짧은 표준 문서 1페이지**를 두고, 마케팅·SNS 담당이 동일 규칙으로 링크를 생성하도록 합니다.

## 9. 기술 삽입 시 참고할 파일 (구현 단계용, 현재 미수정)

코드 작업 시 손대기 쉬운 위치만 미리 짚어 둡니다. **이 문서 작성 시점에는 변경하지 않았습니다.**

| 영역 | 후보 파일 |
|------|-----------|
| 공통 푸터·스크립트 | `js/site-footer-include.js`, `partials/site-footer.html` |
| 셸·GNB | `js/left-gnb-include.js`, `css/shell.css` |
| 페이지별 | 각 `*.html` 의 `</body>` 직전 (최후 수단) |
| API 확장 | `api/src/routes/`, 신규 `analytics` 서비스·테이블 |
| Nginx | `deploy/nginx/55cine.conf` (로그 포맷·real_ip) |

**관리자 제외:** `admin/*.html` 또는 경로 `/admin/` 에는 스니펫을 넣지 않습니다.

## 10. 의사결정 요약

| 우선순위 | 선택 | 이유 |
|----------|------|------|
| **지금 당장** | Nginx 로그 + UTM 규칙 | 코드 없이 유입·인기 URL 파악 가능 |
| **단기 (권장)** | **GA4** 또는 **Umami/Plausible** | 유입·페이지·체류(또는 engagement)를 빠르게 대시보드화 |
| **중기** | 커스텀 이벤트(상세 체류·예매 클릭) | 멀티 페이지 + API 목록 구조에 맞춘 정밀 분석 |
| **장기 (선택)** | 자체 API + DB | 데이터 소유·맞춤 리포트·관리자 통합 |
